# 0012: Audit cuts

## Problem

The audit found copies standing in for derivation (types copied from interfaces, four Result schemas that disagree, child modes copying a parent's playbook), and slices 1 to 5 remove the causes. Slice 6 removes comments that break the rule 0011 adds. Slices 7 and 8 reset the goldens and the guard matrix, which the audit found stale.

## Slices

Each ends with the tests green and `bay check` clean. "Rows" are the cut-list rows of the appendix.

1. **Types derive from code.** A feature's in and out default to its code step's endpoint schema, and a `$ref` may point into a schema. Type lookup falls back past the mode lineage to one shared Result in `components/tools/types/`, which replaces the four copies. Rows a21, a22, a23, a26, a29.
2. **Playbook and rules fall back to the parent.** The resolver reads the lineage as lint already does (`bay/model.py:1181,1201` read only the child). Then mail-briefing's ask playbook and rules, its `mode.yaml` override and its coordinator playbook go, with three generic pieces moved into briefing's ask; feed-briefing's ask gains briefing's no-secrets and author-and-date rules, which the owner confirms at approval. Four fixture tests are rewritten. Rows a27, a28.
3. **Shared helpers and dead branches.** One helper each for the ISO time, the time window, the path guard, the write-tool set, the front-matter parser, the SQL authorizer, the ledger folds, the git file listing and config defaults, plus the dead branches (corpus-store pre-release code, the `fixed` status with no writer). The parser stops emitting the spill-file, compaction and hook-timing outputs, and their fields leave the session schema. Rows a17, b8, b10, b11 (without folding `show --resolved` into `describe`, which stays out of this proposal). Rows b12 and b13 are moved to 0010: connector login into `bay/connect.py`, and lint's `mode_envs` into `bay/model.py`.
4. **Tests named by subject.** `test_boundaries.py` becomes `test_guard.py` and takes the F-2 and F-7 cases of `test_guard_7a.py`; `test_boundary.py` becomes `test_check_base.py`; `test_review7a.py` (at `components/forge/tests/` after 0010 slice 1) is merged into the dispatch, ledger and resolver tests, dropping only the f6-revert duplicate; one helpers module; one home per rule; the duplicates go. Lint then refuses a test file or test name with a slice or round label. Rows a30, a31, a32, b15, b16.
5. **Compact schema formatting.** One formatter writes the data schemas compactly, with `$defs` for repeated tokens, and the environment schema drops its offline block. No content changes. `bay check` then fails on a JSON file the formatter would change. Rows b1, b2, b3, b14.
6. **Comment cleanup.** One commit removes the comments and docstring lines that break the comments rule (0011's `comments` component) and lowers `comment_lines` to the real count. It changes no code: the code with comments stripped is identical before and after. Row b9.
7. **Golden reset.** The owner's decision: the goldens reset once, here. The replay code that rebuilds old output from today's code goes, the stages, improve and offline goldens are regenerated, and from then on goldens are regenerated by one command, a `tests/run.py` option, at each release, in one reviewed commit. `framework/roles/builder.yaml:30` is reworded to say so, still with "never edit a file in a golden/ folder by hand". The improve golden pins its own input, so no test depends on the contents of `HANDOFF.md`. Rows b5, b6, b7.
8. **Guard-matrix reset.** The guard decisions are the safety record, and plans/0008:34 warned that a regeneration can hide a guard change. So this is its own item: the regenerated `guard-matrix.json` (about 254 lines added and 308 removed on the audit's trial) is reviewed line by line, row by row against the old file, before it is approved. It is written one row per line. Row b4.

Slices 1 to 3 add behaviour; the rest remove or reformat.

## Prevention

Same rule as 0010's Prevention: a check, never prose.

| Root cause | Check that blocks it | Slice |
|---|---|---|
| A type copied from an interface | types derive from the code step; lint refuses a type equal to its interface | 1 |
| A schema written one token per line | the formatter; check fails on unformatted JSON | 5 |
| Tests named after review rounds | lint refuses a test file or name with a slice or round label (`7a`, `b1_`) | 4 |
| Goldens kept stale | regenerated only by the release command | 7 |

Out of this proposal, for the next one: improve's triage records for each finding the check that would have caught it, and a finding without one is fixed by adding the check; the file-by-file audit becomes an improve endpoint run at each release; a near-duplicate-function detector joins the `standards` step for new code.

## Kept, not cut

The owner decided that every proposal and plan stays: no history document is deleted, and the audit's removal of proposals 0001 to 0005, 0001a, plans/0008 and `docs/research/` is not part of this proposal. `HANDOFF.md` stays and holds current work only. The audit also found the `role skills:` field and `show --resolved` as candidates; they await a separate decision and are not in a slice.

## Compatibility impact

The guard decisions that `tests/golden/guard-matrix.json` pins are re-pinned only in slice 8, after review.

## Safety impact

Regenerating goldens is allowed only at a release, in one reviewed commit, and the guard matrix gets its own line-by-line review.
