2. `bay/generate-types.ts` lives at `schemas/generate-types.ts`. It still writes `bay/generated/`, and `npm run generate` and `npm run generate:check` still work. It is type-checked, linted, formatted and covered by the dead-code check where it stands.
3. Every import, the feature map, both debt lists, the dead-code configuration, `package.json`, `tsconfig.json`, the lint configuration, and any path in a test, script, schema or document that named an old path is updated.
4. The move is done by a script kept outside the repo, which the reviewer can rerun on the starting commit to get the same tree (P-24). The report gives the script in full.
5. A report.

This slice moves files and nothing else. No name, type, export, behaviour or test assertion changes. No entry file is added; that is M3.

## Instructions

1. Run `npm run check` before any edit, in the foreground, and wait for it. Record test count, kernel line count, both debt counts by rule, and the warnings of `./bay.sh check`.
2. Write the script: the `git mv` calls, the import rewrites, the configuration edits. Run it. Fix imports until typecheck passes, by improving the script, not by hand.
3. Update the map. Regenerate both debt lists and read the diff.
4. Run `npm run check`. Commit. Prove DOD-M1-9 in a throwaway copy. Write the report.

No bug injection in this slice: it changes no behaviour. The evidence is DOD-M1-1, DOD-M1-5 and DOD-M1-9.

## Tools

- A throwaway copy: `git archive <commit> | tar -x -C <new folder under /tmp>`, then link `node_modules` into it.
