# 0001 - agentbay v0.2: modes, roles, agents, environments, connectors

- Status: approved 2026-10-26, amended 2026-10-27 (see below), implemented on branch feat/x-feed
- Feature: forge.extend (first use; recorded after the fact)
- Design: docs/DESIGN.md

## Problem

v0.1 composed agents from Layers into AgentSpecs. That mixes three things that change for
different reasons: what a job is (workflow, definition of done), who does a step (role,
model), and what the step may touch (tools, secrets, network, files). It had no way to run
deterministic code without an agent, no budget or effect enforcement, and no place for
secrets that agents must never see. The first real job (an X feed briefing) needs all of these.

## Change

| concept | v0.1 | v0.2 |
|---|---|---|
| job | - (ad-hoc delegation) | **Mode** with endpoints = **features** (in/out, effects, workflow, playbook, rules, review) |
| who | AgentSpec | **Role** (prompt, doneWhen, uses) placed on an **Agent** (runtime, model, env) |
| what it may touch | Layer tools/clis/mcp | **Environment** (bindings, secrets, network, fs, models, effects, limits) |
| concrete tools | Layer | **Connector** implementing a versioned **capability interface** |
| invocation | Agent tool | `bay call <mode>.<endpoint>` dispatcher (+ `bay submit`, `bay show`, `bay approve`; roles read data via `.agentbay/roles/<role>/use`) |
| checks | review-checklist skill | id'd Definition of Done + rules + deterministic checks + optional review per feature |
| framework | - | `framework/` (read-only to users) with the `forge` mode for create/extend/migrate |

Schemas: `schemas/{mode,role,agent,environment,connector,interface,rules,config}.schema.json`
(apiVersion `agentbay/v2`), data schemas `feed.post/v1`, `feed.coverage/v1`, `review.verdict/v1`.
CLI: `validate`, `lint`, `build`, `clean`, `ls`, `describe`, `call`, `submit`, `show`, `approve`,
`<kind> new`, `migrate`, `secret set`, plus the v0.1 ledger commands.

## Compatibility impact

Breaking: apiVersion `agentbay/v1` AgentSpec and Layer files are rejected with a hint to run
`bay migrate`. Unchanged: TaskEnvelope/Result protocol, ledger format (new event types added),
hook behaviour, adapter guarantees (merge, manifest, idempotent, clean restores originals).

## Migration plan

`bay migrate` (dry-run diff by default, `--confirm` to apply): each worker AgentSpec becomes a
Role on agent `worker` whose `uses` are mapped from its layers (base -> workspace.read/v1,
code -> + workspace.write/v1, research -> + web.research/v1, review -> + git.read/v1);
coordinator specs and Layer folders are removed. The shipped starter content is migrated:
researcher, builder and reviewer roles; the Chief of Staff as the system coordinator; and the
`delivery` mode (research, build + review) keeps the v0.1 behaviour.

## Approved amendments (2026-10-27)

Recorded in full in docs/DESIGN.md, "Approved amendments (2026-10-27)".

- **Kept:** per-role `use` shims for role data access; `maxPostsPerRun` and `costPerPostUsd` caps; agent `model: inherit`.
- **User decision:** keep the `envs: { local-feeds: local-feeds-offline }` config selector for the shipped offline
  env (only envs declaring `substitutes:` can be swapped).
- **Removed:** config-level `bindings` (envs/ are the only place capabilities are bound; rejected if present);
  env `fs.base` (fs paths are project-relative; forge's project is the agentbay checkout, so forge env paths
  resolve as before; rejected if present).
- **Fix round:** PreToolUse(Bash) guard hook with no permission wildcards; deletion re-checks via the official
  `GET /2/tweets?ids=` within the API window; billing on posts returned; one `capability/vN.endpoint` spelling;
  `source`/`window` required on feed.source connectors; `schedule` is declarative.
- **Compatibility:** configs with `bindings` and envs with `fs.base` written against the first implementation
  fail with a message naming the fix; no released version shipped them, so no `bay migrate` step is added.
- **Review round 2 (fixes):** the guard covers file tools too (Read/Edit/Write/MultiEdit/NotebookEdit/
  Glob/Grep) with normalized paths, plus session-wide `Edit` deny rules on `.agentbay/**`, `.claude/**` and the
  kit; git file-writing/exec flags refused; callers with `agent_id` but no `agent_type` treated as unknown
  subagents; approval gates pass only via `bay approve` in a terminal; deletion-check budget reserved before the
  timeline and only verified ids marked; offline env `local-feeds-offline` selected with `envs:` in config
  (no tracked file edited); defaults single-sourced in mode config schemas.
- **Review round 3 (user-approved option B, safety rule):** the guard is defense in depth, not isolation; it
  auto-allows only a role's own read-only shim, nothing that runs code is pre-approved (`bay call`/`submit`
  prompt), the guard fails closed (`onFailure: block`), protected paths are checked by identity and case-folded
  on case-insensitive disks, a wider never-write list applies to all subagents, forge.extend is installed only in
  the agentbay checkout, builder worktree isolation is removed. OS sandbox: next PR.
